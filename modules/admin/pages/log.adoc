= Работа с журналом сообщений сервиса Workflow

Журнал сообщений сервиса Workflow предназначен для просмотра данных по обработке функций сервисом. Настройка журналирования описана в разделе "<<config,Настройка журналирования>>".

При обновлении без замены конфигурационного файла сохраняются прежний формат и настройки журналирования, описанные в разделе "xref:bp-management.adoc[]". Для перехода на JSON примените секцию `NLog` из конфигурационного файла новой поставки модуля, сохранив остальные настройки.

[#view]
== Просмотр сообщений журнала

В новой конфигурации сообщения записываются в формате JSON: одна строка соответствует одному событию. Файловый и консольный журналы используют одинаковый формат.

.По умолчанию файлы журналов находятся в каталогах:
* `%ProgramData%\Docsvision\Workflow` для Windows.
* `/var/log/docsvision/workflow` для Linux.

Сервис Workflow и процессы ExecLogic одной разрядности записывают сообщения в общий файл. Для процессов разрядности 32 и 64 бита используются разные файлы, например `Workflow_64.log` в Windows и `workflow_64.log` в Linux.

Для анализа сообщений конкретного процесса используйте поле `processId`, а для выбора базы данных -- поле `dataBase`. Поле `dataBase` присутствует, если для события известен псевдоним базы данных. Общие поля записи: `timestamp` -- время события, `level` -- уровень, `module` -- имя модуля или логгера, `message` -- сообщение, `processId` -- идентификатор процесса.

Консольный журнал выводится в stdout процесса. В Linux сообщения службы можно просмотреть в системном журнале, в контейнере -- средствами сбора журналов контейнеров.

[#config]
== Настройка журналирования

.Чтобы изменить настройки:
. {blank}
+
[subs="specialchars,attributes,quotes"]
Отредактируйте секцию `NLog` в конфигурационном файле модуля по адресу {config-wf}.
+
. В разделе `NLog.variables` задайте необходимые параметры:
+
* `fileLogLevel` -- задаёт уровень журналирования для файла журнала.
* `consoleLogLevel` -- задаёт уровень журналирования для консоли (stdout/stderr).
* `enableFileLogging` -- включает или отключает ведение журнала в файл.
* `enableConsoleLogging` -- включает или отключает ведение журнала в консоль (stdout/stderr).
+
По умолчанию файловое и консольное журналирование включены, для обоих используется уровень `Error`. Чтобы записывать также информационные сообщения, установите уровень `Info` для нужного канала вывода.
+
. Перезапустите службу Workflow.

Для контейнеров отключите запись в файл: `enableFileLogging` -- `false`, `enableConsoleLogging` -- `true`. Сообщения будут выводиться в stdout контейнера.

Настройки "Файл журнала" и "Уровень журналирования" удалены из разметки {of-mc}. Для новой конфигурации используйте секцию `NLog`.
